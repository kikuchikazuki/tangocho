# 暗記帳アウトプットアプリ 設計書

## 目的

左右に対応する暗記項目を表示し、片側または両側を隠してアウトプット練習できる、ブラウザ完結型の暗記帳アプリを作る。初期データはAWS暗記帳のみとし、ユーザーが後から任意の暗記帳ページを追加できるようにする。

## 対象範囲

- 初期ページとして「AWS暗記帳」を用意する。
- 暗記帳ページを追加し、ページ名を付けられるようにする。
- `左の項目 = 右の説明` の1行1問形式をまとめて貼り付けて追加できるようにする。
- 左右の項目を個別に隠し、タップで個別に表示できるようにする。
- 左または右の全項目を一括で隠す／表示する。
- 左右それぞれに3段階の週次進捗を持たせる。
- ページ単位で左右の進捗を一括クリアできるようにする。
- ページ、問題、表示状態、進捗をブラウザ内に保存する。

## 画面と操作

### ページ管理

画面上部に暗記帳の切り替えとページ追加を配置する。ページ追加ではページ名を入力し、新しい空の暗記帳を作成する。初期状態ではAWS暗記帳だけが存在する。

### 問題追加

現在の暗記帳に対して、複数行のテキストを貼り付ける。各行を最初の `=` で左右に分割し、左側を問い、右側を答えとして登録する。空行や区切りのない行は登録対象から除外する。既存の問題は保持し、貼り付けた問題を追加する。

### 問題表示

問題を左右2列のカードまたは行として表示する。左・右の各セルは独立した表示状態を持ち、隠れているセルをタップするとそのセルだけ表示する。上部の一括操作で左列または右列をすべて隠せる。一括隠しボタンは同じボタンを再度押すと対象列を表示に戻す。左右をすべて表示する操作も用意する。

### 週次進捗

左右それぞれに3つの段階表示を置く。クリックごとに次の状態へ進む。

```text
未達成 → 1週目 → 2週目 → 3週目 → 未達成
```

表示上は、例えば2週目なら `☑ ☑ ☐` とする。左と右は独立して進捗を持つ。

ページ内の操作として、左側のみ、右側のみ、左右両方の進捗を一括クリアできるようにする。

## データモデル

ブラウザの `localStorage` にアプリ状態を保存する。概念モデルは次の通り。

```text
AppState {
  pages: Page[]
  activePageId: string
}

Page {
  id: string
  name: string
  cards: Card[]
}

Card {
  id: string
  left: string
  right: string
  leftReveal: boolean
  rightReveal: boolean
  leftProgress: 0 | 1 | 2 | 3
  rightProgress: 0 | 1 | 2 | 3
}
```

ページ全体の一括隠し状態はUI操作としてカードの各セルへ反映し、ページ切り替え後も個別の表示状態を保持する。初回起動時は組み込みのAWSデータを保存する。

## 技術方針

依存を最小限にしたフロントエンドアプリとして構成し、データ処理、状態更新、表示を分離する。モバイルでも操作しやすい大きめのタップ領域とレスポンシブな2列レイアウトを採用する。

## エラー処理

- ページ名が空の場合は作成しない。
- 貼り付け内容が空の場合は追加しない。
- `=` がない行はスキップし、追加件数を利用者に知らせる。
- 左右どちらかが空になる行はスキップする。
- 保存データが壊れている場合は安全に初期AWSデータへ戻す。

## 検証項目

- 初回起動時にAWS暗記帳だけが表示される。
- 複数行貼り付けで問題が追加される。
- 左右の個別タップ表示が独立して動く。
- 左右の一括隠しと再表示が動く。
- 進捗が0→1→2→3→0の順で切り替わる。
- 左右別、または両方の進捗クリアが動く。
- ページ追加・切り替えが動く。
- 再読み込み後もページ、問題、進捗が残る。
- スマートフォン幅でも操作できる。
