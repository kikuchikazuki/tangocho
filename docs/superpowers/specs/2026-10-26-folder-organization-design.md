# 暗記帳フォルダ整理・問題移動機能 設計書

## 目的

暗記帳を1階層のフォルダで整理し、問題を暗記帳間で個別または一括移動できるようにする。既存データは壊さず、既存の問題に対して分類候補を確認してから反映できる導線を用意する。

## スコープ

- 1階層フォルダの追加・名前変更・削除
- 暗記帳のフォルダ変更と未分類への移動
- 問題の個別移動
- 問題の複数選択・一括移動
- 既存問題の分類候補を確認して反映する画面
- 既存データとの後方互換性

フォルダの入れ子、問題のタグ、コピー機能、分類候補の無確認反映は今回の対象外とする。

## UI構成

ヘッダーに「整理・管理」への導線を追加する。整理・管理画面ではフォルダと暗記帳を一覧表示し、フォルダの作成・編集・削除、暗記帳の所属変更を行う。既存暗記帳は初期状態で「未分類」に表示する。

暗記帳画面では各問題に移動操作を追加する。複数選択時には選択問題を一括移動する操作を表示する。移動先の選択後は確認を求め、移動元から削除して移動先へ追加する。

既存問題の整理では、問題・現在の暗記帳・分類候補を一覧にする。候補は編集可能とし、ユーザーが確認して「反映」を押した場合だけ移動を実行する。

## データモデル

```ts
type Folder = {
  id: string;
  name: string;
};

type Page = {
  id: string;
  name: string;
  folderId: string | null;
  cards: Card[];
};

type AppState = {
  folders: Folder[];
  pages: Page[];
  activePageId: string;
  completionRecords: CompletionRecord[];
};
```

`folderId: null` は未分類を表す。問題のIDと進捗状態は移動時も維持する。カレンダーの完了記録はページIDに紐づくため、問題移動では変更しない。

分類候補は画面上の一時状態として扱い、必要なら次の形式で表現する。

```ts
type ClassificationSuggestion = {
  cardId: string;
  targetPageId: string;
  reason?: string;
  accepted: boolean;
};
```

## 移行と保存

既存の `folders` がない状態を読み込んだ場合は空配列にし、既存 `Page` の `folderId` がない場合は `null` として正規化する。未知のフォルダIDや重複フォルダなど不正な値は保存前に除外または未分類へ戻す。

既存のクラウド保存形式との互換性を維持し、読み込み時・保存時の両方で正規化する。問題移動は1回の状態更新として扱い、途中状態を保存しない。

## エラー処理

- 最後の暗記帳は削除できない
- フォルダ削除時、所属暗記帳は未分類へ移動する
- 移動元と移動先が同じ場合は操作できない
- 選択問題が0件の場合は一括移動できない
- 保存中・保存成功・保存失敗を表示する
- 保存失敗時は変更前の状態へ戻す

## 完成条件とテスト

- 既存データを未分類として読み込める
- フォルダのCRUDと暗記帳の所属変更ができる
- 問題を個別・一括で移動できる
- 移動前確認が表示される
- 分類候補を確認後に反映できる
- 問題の進捗とカレンダー記録が維持される
- 不正な古い保存データが正規化される
- ドメイン、UI、保存処理のテストが成功する
- 本番ビルドが成功する
