# カレンダー達成記録機能 設計書

## 目的

単語帳を学習した日をカレンダーで振り返り、継続のモチベーションを保てるようにする。
最初のリリースでは達成日の色付けに絞り、将来の連続日数や月別集計を追加できるデータ構造にする。

## 対象範囲

- 上部タブから独立したカレンダー画面を開けるようにする
- 現在の単語帳を「今日の学習完了／未完了」で切り替えられるようにする
- カレンダーの日付を選び、その日に完了した単語帳を編集できるようにする
- 1日に複数の単語帳を記録できるようにする
- 達成記録がある日をカレンダー上で色付けする
- 既存のクラウド保存、JSONバックアップ、単語帳削除と整合させる

連続日数、学習時間、通知、カード進捗からの自動判定、日付セルへの単語帳名表示は今回の対象外とする。

## ユーザー体験

### 暗記帳画面

既存の暗記帳タブ群に「カレンダー」タブを追加する。暗記帳を表示しているときは、現在選択中の単語帳に対する「今日の学習を完了」ボタンを表示する。

- 未完了の場合、押すと現在のローカル日付と単語帳IDの組み合わせを追加する
- 完了済みの場合、押すと同じ記録を削除する
- 成功した状態をボタンのラベルや見た目で確認できる
- 記録はカード進捗の状態とは独立させる

### カレンダー画面

- 1か月単位の月表示を行う
- 前月・翌月へ移動できる
- 達成記録が1件以上ある日をオレンジ系の背景色で表示する
- 日付セルには単語帳名を表示せず、色付けを優先する
- 日付を選ぶと、その日の日付と全単語帳の一覧を表示する
- 各単語帳を「完了／未完了」で切り替えられる
- 過去日も同じ操作で追加・取り消しできる
- 同じ日に複数の単語帳を完了できる

カレンダーから暗記帳画面へ戻った場合も、選択中の単語帳を可能な範囲で維持する。

## データ設計

`src/domain/types.ts` に達成記録の型を追加する。

```ts
type CompletionRecord = {
  date: string;
  pageId: string;
};

type AppState = {
  pages: Page[];
  activePageId: string;
  completionRecords: CompletionRecord[];
};
```

### 保存規則

- `date` は `YYYY-MM-DD` の日付だけを保存する
- 現在日付は端末のローカル日付から作る。UTC変換による日付ずれを起こさない
- 同じ `date` と `pageId` の組み合わせは1件だけにする
- 完了操作は既存記録がなければ追加し、あれば削除する
- `completionRecords` は `AppState` の一部として既存のSupabase JSON状態に保存する
- JSON書き出し・読み込みにも達成記録を含める
- 単語帳削除時は、その単語帳の達成記録も削除する

### 後方互換性と入力検証

既存の保存データには `completionRecords` がないため、読み込み時に空配列へ補完する。インポートやクラウドから受け取ったデータについては、次の記録だけを採用する。

- `date` が厳密な `YYYY-MM-DD` 形式で、実在する日付である
- `pageId` が現在の `pages` に存在する
- `date` と `pageId` の重複がない

不正な記録や存在しない単語帳を参照する記録は無視する。既存のカード・単語帳データの扱いは現在のサニタイズ処理を維持する。

## 実装構成

### ドメインロジック

`src/domain/calendar.ts` にUIから独立した処理を置く。

- ローカル日付を `YYYY-MM-DD` に変換する
- 指定月のカレンダー表示日を生成する
- 日付と単語帳IDの達成状態を判定する
- 達成記録を追加・削除する
- 単語帳削除時に関連記録を削除する

記録操作は元の状態を変更せず、新しい配列や状態を返す純粋な関数として実装する。

### UI

`src/components/CalendarView.tsx` を追加し、次を担当させる。

- 月移動ボタン
- 月の日付グリッド
- 達成日の色付け
- 選択日と単語帳一覧
- 完了／未完了の切り替えイベント通知

`src/App.tsx` は暗記帳表示とカレンダー表示の切り替え、選択日、現在の単語帳の完了操作、既存の保存キューとの接続を担当する。カレンダー専用の状態をクラウドへ別保存しない。

## 保存・同期

既存の `saveCloudState` と保存キューを利用する。達成記録の追加・削除も他の状態変更と同じくローカル変更 revision を進め、保存完了前に定期同期の古い状態で上書きしない。

複数端末で同時編集した場合の競合解決は既存仕様に合わせ、最後に保存された `AppState` を採用する。通信に失敗した場合は既存の保存エラーメッセージを表示し、画面上の変更は保持する。

## テスト方針

ドメインテストで次を確認する。

- 同じ日に複数の単語帳を追加できる
- 同じ記録を再度切り替えると削除される
- 過去日を指定して編集できる
- 月初、月末、うるう年を含む月の表示日が正しい
- 達成記録のない日とある日の判定が正しい
- 単語帳削除時に関連記録だけが削除される
- `completionRecords` がない古い状態を空配列として扱える
- 不正な日付、重複、存在しない単語帳IDを読み込み時に除外できる

既存のカード進捗、単語帳追加・削除、JSON入出力のテストとビルドも実行し、回帰がないことを確認する。

## 完了条件

- 上部タブからカレンダー画面を開ける
- 暗記帳画面から現在の単語帳を今日の達成として切り替えられる
- カレンダー上で達成日が色付けされる
- 日付を選んで複数単語帳の完了状態を編集できる
- 過去日を編集できる
- 再読み込み後も達成記録が残る
- 古い保存データが壊れずに読み込める
- 単語帳削除時に不要な達成記録が残らない
- `npm test -- --run` と `npm run build` が成功する
